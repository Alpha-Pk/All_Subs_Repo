=== Duplicate Message problem (24s - 98s) ===

Let's understand with this flow of the duplicate message problem. Now, let's say producer send one batch which has let's say for example, this batch has only one event in it. Okay? Now, broker receive this batch and in the log it will write event one written at offset one. Okay? Let's say this batch has only one event in it. And it send the acknowledgement which get lost because of some network issue. Now, producer will wait for some time and since retry is greater than zero, after some time it will retry it. Okay? The same batch is sent again. Now, the broker receive it again and it will write the same event at let's say offset two. Now, at this point of time in a log there is a duplicate. Same event appear multiple times. Okay? Because today broker has no way to determine it has already written the same event before or not. So, that is the problem one when we have a retry. There is a chance that duplicate messages get recorded into the logs. Another is message reordering issue.
